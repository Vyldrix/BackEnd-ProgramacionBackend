# Modelado de Entidades en Prisma ORM y Migración a PostgreSQL

Este plan describe el diseño y modelado de las entidades **Usuario**, **Producto**, **Pedido** y **DetallePedido** en `schema.prisma`, definiendo sus claves primarias, atributos de precio y stock, y las relaciones Uno a Muchos (1:N), junto con la ejecución de migraciones en PostgreSQL.

---

## Decisiones de Modelado y Relaciones

1. **Credenciales y Conexión en `.env`**:
   - Se actualizará `DATABASE_URL` en `.env` para reflejar la contraseña `postre.sql` configurada por el usuario:
     `postgresql://postgres:postre.sql@localhost:5432/ejercicio_backend?schema=public`

2. **Entidades y Atributos**:
   - **`Usuario`**:
     - `id`: Int `@id @default(autoincrement())`
     - `nombre`: String
     - `email`: String `@unique`
     - `edad`: Int
     - `creadoEn`: DateTime `@default(now())`
     - Relación: `pedidos Pedido[]` (1:N con `Pedido`)
   - **`Producto`**:
     - `id`: Int `@id @default(autoincrement())`
     - `nombre`: String
     - `descripcion`: String
     - `precio`: Float
     - `stock`: Int
     - `creadoEn`: DateTime `@default(now())`
     - Relación: `detalles DetallePedido[]` (1:N con `DetallePedido`)
   - **`Pedido`**:
     - `id`: Int `@id @default(autoincrement())`
     - `usuarioId`: Int (FK hacia `Usuario.id`)
     - `total`: Float `@default(0)`
     - `estado`: String `@default("PENDIENTE")`
     - `creadoEn`: DateTime `@default(now())`
     - Relaciones:
       - `usuario Usuario @relation(fields: [usuarioId], references: [id], onDelete: Cascade)`
       - `detalles DetallePedido[]` (1:N con `DetallePedido`)
   - **`DetallePedido`**:
     - `id`: Int `@id @default(autoincrement())`
     - `pedidoId`: Int (FK hacia `Pedido.id`)
     - `productoId`: Int (FK hacia `Producto.id`)
     - `cantidad`: Int
     - `precioUnitario`: Float
     - `subtotal`: Float
     - Relaciones:
       - `pedido Pedido @relation(fields: [pedidoId], references: [id], onDelete: Cascade)`
       - `producto Producto @relation(fields: [productoId], references: [id], onDelete: Restrict)`

3. **Mapeo de Tablas a PostgreSQL**:
   - Se utilizará `@@map` para respetar convenciones de base de datos relacionales en minúsculas y snake_case:
     - `Usuario` -> `usuarios`
     - `Producto` -> `productos`
     - `Pedido` -> `pedidos`
     - `DetallePedido` -> `detalles_pedidos`

4. **Entidades de Dominio en TypeScript**:
   - Se crearán las clases y contratos de TypeScript correspondientes en `src/entities/`:
     - `pedido.entity.ts`
     - `detalle-pedido.entity.ts`

## Plan de Verificación

### 1. Migración y Creación de Tablas en PostgreSQL
- Ejecutar:
  ```bash
  npx prisma migrate dev --name init_modelos_relacionales
  ```
- O alternativamente crear la base de datos `ejercicio_backend` si no existe y aplicar la migración.
- Verificar mediante `psql` que las 4 tablas (`usuarios`, `productos`, `pedidos`, `detalles_pedidos`) y sus claves foráneas existen en PostgreSQL.

### 2. Generación del Cliente Prisma
- Ejecutar `npx prisma generate` para actualizar los tipos orientados a objetos (`prisma.pedido`, `prisma.detallePedido`, etc.).

### 3. Validación de Compilación y Pruebas Existentes
- Ejecutar `npm run build` para asegurar la correcta compilación TypeScript.
- Ejecutar `npm test` para asegurar que las pruebas existentes continúen pasando.
