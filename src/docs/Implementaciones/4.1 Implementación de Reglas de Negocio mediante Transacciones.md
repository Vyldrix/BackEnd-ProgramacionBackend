# Flujo de Checkout Transaccional con Prisma ORM (ACID)

Este plan describe la implementación del flujo de **checkout de compras** en la capa `Service`, garantizando la integridad de datos mediante transacciones relacionales con `prisma.$transaction`, decremento atómico de inventario, validación crítica de stock con **ROLLBACK** automático y confirmación (**COMMIT**) con cálculo de totales y detalles.

---

## Decisiones de Diseño y Reglas de Negocio

1. **Garantía ACID mediante `prisma.$transaction`**:
   - Todo el proceso de compra se ejecutará dentro de un bloque interactivo `await prisma.$transaction(async (tx) => { ... })`.
   - Si cualquier operación falla o si se lanza un error dentro del callback, Prisma ejecutará un **ROLLBACK** en PostgreSQL, revirtiendo todas las modificaciones (pedido, detalles y stock).
   - Al finalizar el bloque sin excepciones, Prisma ejecutará un **COMMIT** automático.

2. **Pasos del Flujo de Checkout**:
   1. **Validación previa**: Validar formato de entrada (`usuarioId` válido, lista de `items` con cantidades enteras mayores a 0).
   2. **Verificación de Usuario**: Confirmar que el usuario existe en la base de datos dentro de la transacción.
   3. **Creación del Pedido Inicial**: Insertar el registro en la tabla `pedidos` con estado inicial `PENDIENTE` y total `0`.
   4. **Procesamiento de Productos**:
      - Por cada ítem, consultar el producto y su stock actual.
      - **Validación crítica**: si `producto.stock - item.cantidad < 0`, lanzar `InsufficientStockError` para disparar el **ROLLBACK** inmediato.
      - Si hay stock suficiente, actualizar el inventario (`stock = stock - item.cantidad`) mediante `tx.producto.update`.
      - Calcular `subtotal = cantidad * precioUnitario` y acumular en `total`.
      - Crear el registro en `detalles_pedidos` vinculado al `pedido.id` y `producto.id`.
   5. **Confirmación y Actualización**:
      - Actualizar el pedido con el total final y cambiar estado a `CONFIRMADO`.
      - Retornar el DTO de respuesta con los datos consolidados.

3. **Manejo de Errores**:
   - Se creará el error de dominio `InsufficientStockError` en `src/services/errors/app.errors.ts` (código HTTP 400 Bad Request o 409 Conflict).
   - El middleware global de errores responderá con el mensaje correspondiente al cliente HTTP.
