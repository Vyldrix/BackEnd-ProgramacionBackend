# Configuración de Conexión a PostgreSQL e Inicialización de Prisma ORM

Este plan detalla los pasos para migrar la capa de persistencia hacia una base de datos relacional **PostgreSQL**, gestionando las credenciales y la cadena de conexión mediante variables de entorno en `.env`, e inicializando **Prisma ORM** para interactuar con la base de datos a través de métodos orientados a objetos en TypeScript/Node.js.

---

## Decisiones de Arquitectura y Diseño

1. **Gestión de Entorno Segura (`.env` y `.env.example`)**:
   - Se definirán variables individuales para las credenciales (`DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`, `DB_NAME`).
   - Se compondrá la cadena estándar requerida por Prisma:
     `DATABASE_URL="postgresql://${DB_USER}:${DB_PASSWORD}@${DB_HOST}:${DB_PORT}/${DB_NAME}?schema=public"`
   - Se mantendrá `.env.example` documentando cada variable para nuevos entornos.

2. **Inicialización y Modelado en Prisma ORM**:
   - Se instalarán `prisma` (CLI) y `@prisma/client` (motor ORM orientado a objetos) junto con `dotenv`.
   - Se creará el archivo `prisma/schema.prisma` configurando el proveedor `postgresql` y mapeando los modelos de dominio:
     - `Usuario` (`id`, `nombre`, `email`, `edad`, `creadoEn`)
     - `Producto` (`id`, `nombre`, `descripcion`, `precio`, `stock`, `creadoEn`)

3. **Abstracción Orientada a Objetos en Capa de Repositorios**:
   - Se implementarán `UsuarioPrismaRepository` y `ProductoPrismaRepository` en `src/repositories/prisma/`.
   - Cada repositorio utilizará los métodos orientados a objetos del cliente Prisma (`prisma.usuario.create`, `prisma.usuario.findMany`, `prisma.usuario.findUnique`, `prisma.usuario.update`, `prisma.usuario.delete`).
   - Se actualizarán las interfaces `IUsuarioRepository` e `IProductoRepository` para operar con `Promise`, permitiendo compatibilidad plena y asincronía en servicios y controladores.

4. **Entorno Local de PostgreSQL (Opcional pero recomendado)**:
   - Se incluirá un archivo `docker-compose.yml` para levantar una base de datos PostgreSQL local en un solo comando (`docker compose up -d`) con los datos configurados en `.env`.
