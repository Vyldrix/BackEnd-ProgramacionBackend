# Especificación OpenAPI e Integración de Swagger UI en Express

Este plan detalla la creación del archivo de especificación OpenAPI (versión recomendada 3.2.0) para documentar declarativamente la API —en particular el endpoint `POST /api/pedidos` con sus DTOs y respuestas— y la integración de **Swagger UI** como middleware en Express para realizar pruebas interactivas desde el navegador.

---

## Decisiones de Diseño y Especificación

1. **Información Base de la API**:
   - `openapi`: `"3.2.0"` (o `"3.1.0"` / `"3.0.3"` en Swagger UI para compatibilidad total con renderizado).
   - `info`:
     - `title`: "API de Comercio y Pedidos - Programación Backend"
     - `version`: "1.0.0"
     - `description`: "Especificación interactiva de la API para gestión de Usuarios, Productos y Checkout de Pedidos con persistencia relacional en PostgreSQL."
   - `servers`: `[{ "url": "http://localhost:3000", "description": "Servidor de Desarrollo Local" }]`.

2. **Documentación Declarativa de `POST /api/pedidos`**:
   - **Ruta y Método**: `POST /api/pedidos`.
   - **Summary & Description**: Registro y procesamiento transaccional de pedidos (checkout).
   - **RequestBody**:
     - `application/json` con esquema basado en los DTOs:
       - `usuarioId`: entero positivo (`type: integer`, `example: 1`).
       - `productosComprados`: lista de objetos con `productoId` (entero positivo) y `cantidad` (entero >= 1).
     - Ejemplos claros de payload.
   - **Respuestas (Responses)**:
     - `201 Created`: Pedido procesado exitosamente con ID, total, estado `CONFIRMADO` y array de detalles.
     - `400 Bad Request`: Información incompleta (falta de campos obligatorios) o stock insuficiente.
     - `422 Unprocessable Entity`: Formato o tipo de datos semánticamente inválido.
     - `404 Not Found`: Usuario o producto no encontrado.

3. **Ubicación del Archivo de Especificación**:
   - Se creará `src/docs/openapi.json` (y opcionalmente `openapi.yaml`) estructurado y tipado.

4. **Integración de Swagger UI**:
   - Instalar `swagger-ui-express` y `@types/swagger-ui-express`.
   - Exponer la interfaz interactiva en la ruta `/api/docs` (y redirigir `/docs`).
   - Permitir pruebas interactivas ("Try it out") directamente desde el navegador web.
